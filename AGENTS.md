# Порядок работы над задачами

Когда пользователь ставит задачу, сначала обдумай, как её выполнить и какие смежные доработки помогут лучше решить задачу. Для подготовки предложения можно изучить контекст и прочитать нужные файлы.

Опиши основной подход. Если есть конкретные идеи для смежных доработок, перечисли их отдельно от основного предложения и кратко объясни пользу каждой.

После отправки предложения дождись ответа пользователя с явным подтверждением подхода или разрешением приступать. Только после такого ответа начинай реализацию, вноси правки и публикуй изменения. Реализуй только согласованные пункты. Если пользователь прямо попросил приступить сразу без согласования, следуй его указанию.

# Публикация изменений

После проверки каждой готовой правки сразу создай коммит с изменениями по задаче и отправь его в удалённый репозиторий, если пользователь не попросил оставить правку локально.

Для читалки репозиторий публикации — `Fizer9/library`, ветка `main`. Если рабочая папка не является Git-репозиторием, используй отдельный клон. Для правок читалки сначала запусти `node scripture-reader/build-pages.mjs` в исходной рабочей папке, затем перенеси изменённые файлы из `scripture-reader/pages-dist` в клон. После пуша проверь, что изменение опубликовано на GitHub Pages.
