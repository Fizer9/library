# Порядок работы над задачами

Когда пользователь ставит задачу, сначала тщательно обдумай, как её выполнить и какие идеи могут быть полезны для самой задачи или смежных вопросов. Опиши пользователю выбранный подход и предложи такие идеи, если они есть. Только после этого приступай к выполнению. Если пользователь прямо попросил действовать иначе, следуй его указанию.

# Публикация изменений

После проверки каждой готовой правки сразу создай коммит с изменениями по задаче и отправь его в удалённый репозиторий, если пользователь не попросил оставить правку локально.

Для читалки репозиторий публикации — `Fizer9/library`, ветка `main`. Если рабочая папка не является Git-репозиторием, используй отдельный клон. Для правок читалки сначала запусти `node scripture-reader/build-pages.mjs` в исходной рабочей папке, затем перенеси изменённые файлы из `scripture-reader/pages-dist` в клон. После пуша проверь, что изменение опубликовано на GitHub Pages.
